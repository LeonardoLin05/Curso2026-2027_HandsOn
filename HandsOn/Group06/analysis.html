1.2 Schema

Group CSV columns Expected RDF treatment
Identification PK, NOMBRE, TIPO PK is a local identifier. NOMBRE is a label. The source file determines whether the resource is a library or a museum.
Description and services DESCRIPCION-ENTIDAD, HORARIO, EQUIPAMIENTO, TRANSPORTE, DESCRIPCION, ACCESIBILIDAD Text values become literals. Accessibility contains one or more codes separated by commas.
Official page CONTENT-URL IRI of the municipal information page.
Address NOMBRE-VIA, CLASE-VIAL, TIPO-NUM, NUM, PLANTA, PUERTA, ESCALERAS, ORIENTACION, CODIGO-POSTAL Address components are literals. Postal codes are strings, not numbers.
Administrative area LOCALIDAD, PROVINCIA, COD-BARRIO, BARRIO, COD-DISTRITO, DISTRITO City, district and neighbourhood are resources. Codes are used in their identifiers.
Coordinates COORDENADA-X, COORDENADA-Y, LATITUD, LONGITUD X/Y are projected coordinates. Latitude and longitude are decimal values.
Contact TELEFONO, FAX, EMAIL Contact values are literals. Missing values are not generated as empty RDF statements.

Important missing values:

  • Libraries: 16 missing entity descriptions, 1 missing equipment value, 3 missing general descriptions, 2 missing district codes and 2 missing neighbourhood codes.

The accessibility field is not a single number. It contains codes such as 1, 1,6 and 1,5,6. Each code should be split and represented separately according to the official data dictionary.

1.4 Data cleaning decisions

  • Decode the input files as Windows-1252 and write RDF files as UTF-8.
  • Keep PK, district codes, neighbourhood codes and postal codes as strings.
  • Trim surrounding spaces but keep the original text of names, schedules and descriptions.
  • Convert latitude and longitude to decimals and validate them against the ranges found above.
  • Omit triples for empty cells.
  • Do not create a district resource from the invalid museum value DISTRITO until the record is corrected.

3. Resource naming strategy

3.1 Base domain and namespaces

The project will use the persistent HTTPS domain https://w3id.org/madrid-culture/. This is different from the default namespace generated by Protégé. The group must register the redirect with w3id.org before public deployment.

Purpose Namespace Prefix
Ontology https://w3id.org/madrid-culture/ontology/ mc:
Individuals https://w3id.org/madrid-culture/resource/ mcr:

Ontology terms and individuals use different paths. Classes and properties are defined directly under /ontology/. Property URIs are not placed below a class URI.

3.2 Ontology term patterns

Type Pattern Examples
Class https://w3id.org/madrid-culture/ontology/{ClassName} mc:Facility, mc:Library, mc:Museum, mc:District
Object property https://w3id.org/madrid-culture/ontology/{propertyName} mc:locatedInDistrict, mc:locatedInNeighbourhood
Datatype property https://w3id.org/madrid-culture/ontology/{propertyName} mc:name, mc:openingHours, mc:latitude

Class local names start with a capital letter. Property local names start with a lower-case letter and use lower camel case.

3.3 Individual patterns

Resource type URI pattern Example
Museum https://w3id.org/madrid-culture/resource/museum/{PK} https://w3id.org/madrid-culture/resource/museum/2058
Library https://w3id.org/madrid-culture/resource/library/{PK} https://w3id.org/madrid-culture/resource/library/25526
District https://w3id.org/madrid-culture/resource/district/{COD-DISTRITO} https://w3id.org/madrid-culture/resource/district/10
Neighbourhood https://w3id.org/madrid-culture/resource/neighbourhood/{COD-DISTRITO}-{COD-BARRIO} https://w3id.org/madrid-culture/resource/neighbourhood/9-7
City https://w3id.org/madrid-culture/resource/city/{slug} https://w3id.org/madrid-culture/resource/city/madrid

Different classes use different paths, for example /museum/ and /library/. Facility names are not used in URIs because names may change. The municipal PK is stable and unique inside each source file. A neighbourhood URI contains both district and neighbourhood code because neighbourhood codes may repeat in different districts.

3.4 URI and publication rules

  • Use HTTPS slash URIs.
  • Use lower-case path segments and ASCII characters.
  • Do not include spaces, accents, file extensions or query parameters in canonical resource URIs.
  • Do not change an existing URI when a name or description changes.
  • When an ontology term is replaced, keep its URI and mark it as deprecated instead of reusing it for another meaning.

3.5 Content negotiation

Canonical ontology and resource URIs will return an HTTP 303 redirect according to the requested representation:

  • Accept: text/html - HTML documentation.
  • Accept: text/turtle - Turtle representation.
  • Accept: application/ld+json - JSON-LD representation.
  • Requests without a supported Accept header - HTML by default.

The w3id.org configuration will redirect to files hosted in the Group06 GitHub repository. The canonical identifiers remain unchanged if the files move.

3.6 Links to external resources

Verified equivalents may be linked to Wikidata. For example, Madrid can link to Q2807 and Museo del Prado can link to Q160112. owl:sameAs will only be used when both URIs identify the same real-world entity.
